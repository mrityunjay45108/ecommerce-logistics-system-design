Courier Partners
1
Customer places an order on the platform.
2
Order and shipment intent are written to PostgreSQL (Outbox Pattern) in the same transaction.
3
Outbox Poller reads unprocessed events and publishes them to Kafka.
4
Courier Logistics Engine consumes events from Kafka topic.
5
Inbox pattern ensures idempotency (duplicate events are acknowledged and dropped).
6
Domain State Machine validates business rules and allows only forward state transitions.
7
Courier Adapter communicates with 3rd-party courier APIs asynchronously.
8
Courier partner processes the request and returns AWB / updates which come back as webhooks/events to the system.
Key Benefits
✔ No latency impact on Checkout
✔ No dual-write / partial failure issues
✔ At-least-once delivery with idempotency
✔ Out-of-order webhooks handled via state machine
✔ Scalable & Resilient Architecture
