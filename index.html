// prisma/schema.prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model Order {
  id            String        @id @default(uuid())
  userId        String
  totalAmount   Decimal       @db.Decimal(10, 2)
  status        OrderStatus   @default(PENDING)
  items         OrderItem[]
  shipment      Shipment?
  outboxEvents  OutboxEvent[]
  createdAt     DateTime      @default(now())
}

// Transactional Outbox Table
model OutboxEvent {
  id            String        @id @default(uuid())
  orderId       String
  order         Order         @relation(fields: [orderId], references: [id])
  topic         String        // "courier.shipment.events"
  payload       Json
  status        OutboxStatus  @default(UNPROCESSED)
  createdAt     DateTime      @default(now())
}

// Idempotent Consumer (Inbox Table in Courier Service)
model KafkaProcessedEvent {
  eventId       String        @id
  topic         String
  processedAt   DateTime      @default(now())
}
1

Customer Initiates Checkout

Customer sends POST /api/v1/orders/checkout with cart items, shipping address, and payment method.

2

Atomic SQL Transaction (Order + Outbox)

E-Commerce Service commits Order, Shipment Intent, and Outbox Event into PostgreSQL within a single atomic transaction.

3

Outbox Poller / Debezium CDC Stream

Outbox Poller queries unprocessed events from PostgreSQL WAL, publishes them to Kafka, and marks them as PROCESSED.

4

Kafka Delivers to courier.shipment.events

Apache Kafka guarantees durable, ordered message retention partitioned by order_id.

5

Courier Service Deduplication (Inbox Pattern)

Consumer checks KafkaProcessedEvent table. If the event ID was previously processed, it drops the message to prevent duplicate AWB generation.

6

Courier Adapter Calls Delhivery / Shiprocket

Adapter translates payload into courier-specific API request, fetches AWB tracking number, and initialises Tracking State Machine.
